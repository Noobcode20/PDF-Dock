# PDF Dock shell and library audit

Date: 2026-11-04. Scope: `src/main.jsx`, Home/Recent/New Document pages, Sidebar, TabBar, CommandPalette, Onboarding and keyboard shortcuts. Checkout was already dirty; no app files were modified. Severity indicates user impact. **Code confirmed** means directly follows from current source; runtime confirmation is explicitly marked separately.

## Findings

1. **High — Cancel/Don't Save on a dirty navigation request executes the navigation.** Type: code confirmed. Trigger: edit a PDF, choose Home/another page, then click Cancel (or Don't Save) in the unsaved dialog. Expected: Cancel keeps editor open; actual: `cancelLeaveRequest` discards draft/dirty state, clears dialog, and invokes `request.action()` (main.jsx:356-365). The action can close the tab or navigate away. This is both misleading Cancel semantics and an unsafe discard path. Proposed: separate dismiss from discard; only discard action should clear draft and continue.

2. **High — Command-palette recent-file open loses source/library identity.** Type: code confirmed. Trigger: open a library PDF from palette Recent Documents and then save/replace it. Palette creates a File with bytes/name only (CommandPalette.jsx:42-49); unlike Home/Recent page open, no `sourcePath` or `libraryId` is attached (HomePage.jsx:387-394; RecentFilesPage.jsx:65-73). Engine save/update path therefore cannot identify the existing library record and may create a duplicate/new identity. Proposed: propagate record.sourcePath and record.id as sourcePath/libraryId.

3. **Medium — Tab-bar remove button can remove the last dirty tab without dirty guard.** Type: code confirmed. Trigger: dirty a PDF and activate that tab’s close button. `closeTab` requests leave, but confirm's Don't Save routes into closeTabNow; if sole tab, it disposes files and closes window (main.jsx:538-563). This follows explicit user discard, so behavior is valid; improvement: make the last-tab action wording clearly say it closes the app/window, not merely tab. (Marked improvement rather than defect.)

4. **Medium — Global “S” and “A” single-key shortcuts steal ordinary keyboard input.** Type: code confirmed. Trigger: press plain `s` or `a` while focus is on a non-editable control, e.g. sidebar/button or library row. Global handler always prevents default and redirects focus on Home (main.jsx:1007-1019; inspect exact current line range if code shifts). Expected conventional typing/assistive behavior; actual focus jumps, and `s`/`a` cannot activate/type in some focused custom controls. Proposed: remove these undocumented global bindings or scope to an explicit non-interactive workspace target.

5. **Medium — Home library has filtering but no sorting control.** Type: improvement. Trigger: accumulate multiple files, attempt to sort by name/size/last opened. Home derives `visibleFiles` only via name substring filter (HomePage.jsx:251-253); header presents Name/size/pages/last opened without sort affordances (620-623). Expected sortable library for these displayed columns; actual insertion order only. Proposed: accessible sort buttons and stable order indicators.

6. **Medium — Home multi-selection can retain hidden filtered-out records.** Type: code confirmed. Trigger: select several files, then type a name filter excluding one selected file and run bulk remove/tool action. Filter only changes rendered list (HomePage.jsx:251-253); bulk operations use all `files` and `selectedFiles` (399-400, 452-459, 550-554). Hidden files remain actionable without visible confirmation context. Proposed: clear selection on query change or constrain bulk action to visible selection, and disclose target names/count.

7. **Medium — Range selection only adds IDs and never removes the old range.** Type: code confirmed. Trigger: select a range with Shift, then Shift-select a shorter/different range from same anchor. `selectFileRange` unions new range into current Set (HomePage.jsx:274-280). Expected range selection replaces previous range; actual discontiguous stale selection persists and bulk actions include it. Proposed: derive range from anchor plus intentional modifier selections.

8. **Medium — Command palette recent-file load can update state after close/unmount.** Type: code confirmed. Trigger: open palette, start getRecentFiles, quickly close or navigate/unmount. Promise handler calls setRecentFiles without cancellation (CommandPalette.jsx:31-40). It may update stale component state; repeated opens can also let older response overwrite newer results. Proposed: active flag/request sequence and reset results on open.

9. **Medium — Palette openRecent failures are invisible for mouse clicks.** Type: code confirmed. Trigger: stale/corrupt library recent record, click it in palette. `openRecent` catches and stores `recentError` (42-50), but click handler's error paragraph lives inside `.palette-results`, which is rendered only when `showCommands` (size maximized or query nonempty; 76 and 118). In compact mode with empty query, the error can be hidden as the palette closes? Click path does not close on failure, leaving compact mode with no results and no visible error. Proposed: surface errors outside `showCommands` or force result region when error exists.

10. **Medium — New Document picker active index can point beyond filtered list after results change.** Type: code confirmed. Trigger: keyboard-navigate to a recent result, then change query to no matches. Query handler resets to 0 only if query nonempty and has a match; otherwise it sets 0, so this path is covered. No defect found; omitted from issue count.

11. **Low — Onboarding completion/initial setup needs clean-profile testing.** Type: improvement / runtime not probed. Startup logic skips onboarding if any legacy setup key exists (main.jsx:145-149), regardless of onboarding-complete marker. This is intentional migration behavior per code comments/history; no standalone defect asserted.

12. **Medium — RecentFilesPage stale-load race can overwrite a newer list.** Type: code confirmed. Trigger: page mounts and starts refresh; focus/visibility causes a second refresh; slower first response resolves last. `refresh` independently writes results (RecentFilesPage.jsx:49-63), with no request ordering/cancellation. Expected latest snapshot; actual stale snapshot can replace it. Proposed: request sequence/active guard.

13. **Low — RecentFilesPage open/remove controls have no in-flight guard.** Type: code confirmed. Trigger: double-click Open in Workspace or confirm Remove repeatedly during IPC. `open` and `deleteFile` have no busy state (RecentFilesPage.jsx:65-87); duplicate reads/navigation or overlapping remove calls can occur. Proposed: disable row actions while operation is pending.

14. **Low — Shortcut display labels may not reflect effective custom modifier matching.** Type: code confirmed. Trigger: save a custom shortcut with metaKey+ctrlKey false/true combinations, inspect palette labels on platform variants. Matching has platform-specific normalization (keyboardShortcuts.js:27-42), while label logic renders metaKey as ⌘ irrespective of OS (CommandPalette.jsx:9-22). Potential mismatch for custom shortcuts. Proposed: centralize formatter next to matcher and test platform matrix.

## Runtime probes and limitations

- Browser runtime successfully opened at `http://127.0.0.1:5174` using an isolated Ego Browser task; Home rendered, workspace tab/sidebar and empty library visible. Task-owned browser context was closed after probe.
- No real library fixtures were added, no user storage was cleared, and no actual documents were removed. Consequently selection, sort/filter with populated records, dirty-close and file-picker persistence were not runtime exercised.
- No Electron isolated fixture was launched in this pass. The findings above are source-confirmed; they should not be represented as runtime reproduced. Shortcut event behavior likewise has not been exercised against a real event loop.
- Scope source tracing did not reveal a sorting implementation elsewhere for Home; recent backend stores/retrieves records and has removal/read safeguards, but does not supply UI sorting.
