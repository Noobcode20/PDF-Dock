# PDF Dock text editor adversarial audit

Scope: text selection/add/edit/layout, fonts, inspector, text undo/redo. All findings below are source-confirmed and reachable from the text editor. Browser reproduction was attempted against current dev server `http://127.0.0.1:5174`; preview opened successfully, but `preview_snapshot` timed out, so none are claimed as runtime reproduced. No app source changed.

## Findings

1. **High — Undo omits important formatting state.** Classification: code-confirmed. Steps: edit text, change alignment/opacity/bold via inspector, then invoke text undo. Expected: previous formatting state restored. Actual: history signature excludes opacity, lineHeight, alignment, bold/italic and local font identity/data, so those changes are not recorded (or are only partially restored). Consequence: undo can leave the editor in a mixed state. Evidence: [textInputHistory.js](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/textInputHistory.js:1), [RichTextInput.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/RichTextInput.jsx:46). Fix: include the complete editable style model in signature/snapshots.
2. **High — Text history is keyed to the mounted input and can reset across edits.** Classification: code-confirmed. Steps: edit paragraph A, commit, edit paragraph B, invoke undo. Expected: coherent document-level undo. Actual: history lives in RichTextInput `useRef`; input is keyed by edit key and unmount cleanup clears global history state. Consequence: undo scope is transient and loses earlier edits. Evidence: [RichTextInput.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/RichTextInput.jsx:33), [ToolStudioPage.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/pages/ToolStudioPage.jsx:3722). Fix: own history in workspace/document state.
3. **High — Negative tracking is silently discarded at PDF export.** Classification: code-confirmed. Steps: set Tracking below zero in TextInspector and commit. Expected: tighter character spacing. Actual: writer advances by `Math.max(0, length-1) * letterSpacingPt`, while PDF character spacing is passed as supplied; inspect operation lines 195–197. Consequence: visual preview and exported placement diverge for negative tracking. Evidence: [operations.js](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/operations.js:195). Fix: apply signed spacing to cursor and text measurement.
4. **Medium — Tracking permits values beyond its declared maximum.** Classification: code-confirmed. Steps: type 30 into Letter spacing. Expected: clamp to max 20. Actual: numeric input has min/max attributes only; update stores `Number(value)` directly. Consequence: extreme spacing can blow out layout/export. Evidence: [TextInspector.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/components/TextInspector.jsx:18). Fix: clamp in update and validate finite values.
5. **Medium — Zero tracking cannot be reliably represented.** Classification: code-confirmed. Steps: set nonzero tracking then set 0. Expected: exact zero tracking. Actual: RichTextInput uses truthy `letterSpacingPt` before fallback and the preview uses same truthy branch; zero falls through to legacy `letterSpacing` or normal. Evidence: [RichTextInput.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/RichTextInput.jsx:127), [ToolStudioPage.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/pages/ToolStudioPage.jsx:3722). Fix: use nullish checks.
6. **Medium — Local-font selector can lose existing family option.** Classification: code-confirmed. Steps: select local font, then reopen family selector. Expected: selected font remains identifiable. Actual: option value becomes `local:<id>` while label is local name; the current style’s system family is omitted due to `!style.localFontId`. Evidence: [TextInspector.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/components/TextInspector.jsx:7). Fix: preserve explicit selected local font and family metadata as separate options.
7. **Medium — Local font IndexedDB transaction may remain open on request error.** Classification: code-confirmed. Steps: cause a font store request failure, then retry list/save. Expected: cleanly closed DB and surfaced error. Actual: request.onerror rejects but only transaction completion/error closes DB. Evidence: [localFonts.js](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/localFonts.js:17). Fix: close database in request error handler and guard transaction lifecycle.
8. **Medium — Selection offsets use text-node string lengths, not grapheme positions.** Classification: code-confirmed. Steps: select text around emoji/combining accents, toggle formatting, then type. Expected: selection preserved at visual character boundaries. Actual: offsets use JS UTF-16 length and restoration walks text nodes by code units. Consequence: caret/range can split surrogate pairs or combining sequences. Evidence: [RichTextInput.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/RichTextInput.jsx:9), [RichTextInput.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/RichTextInput.jsx:20). Fix: use grapheme-aware mapping or preserve native Range across DOM replacement.
9. **Medium — Paste always strips rich text without preserving mixed formatting.** Classification: code-confirmed. Steps: paste bold/colored text into a formatted selection. Expected: documented paste behavior or source formatting retained. Actual: handler inserts plain text only. Evidence: [RichTextInput.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/RichTextInput.jsx:152). Fix: either document plain-text paste or parse clipboard styles into style ranges.
10. **Medium — Font-weight control is only binary.** Classification: code-confirmed. Steps: edit source text with weight 500/600/800 and inspect/select Regular/Bold. Expected: current actual weight and available weights represented. Actual: inspector reduces any style to bold boolean and writes only 400 or 700. Evidence: [TextInspector.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/components/TextInspector.jsx:13), [ToolStudioPage.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/pages/ToolStudioPage.jsx:3474). Fix: retain numeric weight where supported.
11. **Medium — Line-height control updates inspector style but rendered rich input ignores it.** Classification: code-confirmed. Steps: change line height while editing selected text and compare line spacing. Expected: immediate preview change. Actual: RichTextInput span style omits lineHeight in non-source-layout rendering; only outer input line height is used. Evidence: [TextInspector.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/components/TextInspector.jsx:17), [RichTextInput.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/RichTextInput.jsx:132). Fix: apply line-height per run or clearly scope control to whole box.
12. **Medium — Wrap measurement ignores letter spacing.** Classification: code-confirmed. Steps: enter a long line and raise tracking until it should wrap. Expected: layout wraps at rendered width. Actual: fit measures scrollWidth/height while text run rendering applies tracking, but styled PDF layout width calculations use font metrics only. Evidence: [styledText.js](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/styledText.js:18), [RichTextInput.jsx](/Users/udbhavp/Desktop/My%20Work/Tools/PDF%20Tools/src/editor/RichTextInput.jsx:125). Fix: include tracking in width calculations.
